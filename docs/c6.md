# C6 Consignado

Camada que fala com a API do C6 para contrato novo e refinanciamento INSS
([decisão 0026](decisoes/0026-contrato-novo-e-refinanciamento-inss-no-c6.md)).
Por enquanto só existe o cliente: nenhum nó do agente o chama e ele não é
montado em `web/composicao.py`. A portabilidade continua sem API.

A fonte é o "Manual API V31.5" do banco (03/08/2026). Ele não está no
repositório; o que foi usado dele está nesta página.

## Onde está cada coisa

| Arquivo | O que faz |
| --- | --- |
| `apps/core/src/saturday/bancos/c6/cliente.py` | HTTP, token, simulação, inclusão, consulta e link de formalização |
| `simuladores/c6/app.py` | Simulador |
| `apps/core/tests/test_c6_cliente.py` | Cliente contra o simulador |

## Ligar

`SATURDAY_C6_ATIVO=true` exige `SATURDAY_C6_BASE_URL`, `SATURDAY_C6_USUARIO`,
`SATURDAY_C6_SENHA` e `SATURDAY_C6_CODIGO_PROMOTORA`. O endereço não tem valor
padrão: o manual só traz o de produção, e o banco não tem ambiente de
homologação. Fora de produção, a `BASE_URL` aponta para o simulador.

## O que o manual define

| Operação | Rota | `Accept` |
| --- | --- | --- |
| Login | `POST /auth/token` (formulário `username` e `password`) | não tem |
| Simulação | `POST /marketplace/proposal/simulation` | `application/vnd.c6bank_error_data_v2+json` |
| Inclusão | `POST /marketplace/proposal` | `application/vnd.c6bank_error_data_v2+json` |
| Consulta | `GET /marketplace/proposal?proposalNumber=` | `application/vnd.c6bank_fgts_consult_v2+json` |
| Link de formalização | `GET /marketplace/proposal/formalization-url?proposalNumber=` | `application/vnd.c6bank_url_consult_v1+json` |

- **Token:** o login devolve `access_token` e `expires_in_seconds` (1199 no
  exemplo). Vai no cabeçalho `Authorization` sem "Bearer".
- **Simulação:** `operation_type` (`NOVA` ou `REFINANCIAMENTO`),
  `product_type_code` (`0001` margem livre, `0002` refinanciamento),
  `simulation_type` (`POR_VALOR_SOLICITADO` com `requested_amount`, ou
  `POR_VALOR_PARCELA` com `installment_amount`), `formalization_subtype`,
  `promoter_code`, `covenant_group` (`INSS`), `public_agency` (`000001`),
  `installment_quantity`, `client` (`tax_identifier`, `enrollment`,
  `birth_date`, `income_amount`) e, no refinanciamento,
  `refinancing_contracts`. A resposta traz convênio, produto, parcela, IOF,
  taxas e `client_amount`, o valor na conta do cliente.
- **Inclusão:** devolve `proposal_number`. O corpo repete os valores da
  simulação em `credit_condition` e leva `origin` (com `typist_code` e
  `tax_identifier_of_certified_agent`), `payment` e `client` com documento,
  estado civil, sexo, nome da mãe e do cônjuge, e-mail, celular, endereço,
  conta, `benefit_data` e `professional_data` (`enrollment` e `benefit_type`).
  O cliente do Saturday só transporta esse corpo; quem o monta é a fase de
  digitação.
- **Despesas (`expenses`):** são os pacotes de seguro. O Saturday não envia
  nenhuma.

## Cliente

- **Token:** em memória, por processo, renovado 1 min antes de vencer. Em 401,
  renova e repete uma vez.
- **Retry:** GET repete uma vez em erro de rede ou 5xx, depois de 1,5 s. POST
  nunca repete. POST sem resposta conclusiva (timeout, 5xx, 2xx sem número de
  proposta) vira `ErroIncerto`; erro de conexão antes do envio é `ErroC6`.
- **Inclusão incerta:** a API não busca proposta por CPF, então não há como
  conferir se a proposta entrou. Quem chama não repete: abre alerta para um
  atendente (regra 4).
- **Registro:** cada chamada grava em `chamadas_externas` método, rota sem
  query string, status e duração.

## Simulador

`uvicorn app:app --app-dir simuladores/c6 --port 8300`. Usuário e senha por
`SIMULADOR_C6_USUARIO` e `SIMULADOR_C6_SENHA`. Confere o token sem "Bearer", o
`Accept` de cada rota e os campos obrigatórios da simulação. `CONFIG` muda a
taxa, a validade do token e o saldo de cada contrato refinanciado; `FALHAS`
programa um erro por rota, com `registrar` para executar a operação antes de
falhar. Os valores são uma conta Price simples, não a tabela do banco. Ainda
não está no `compose.override.yaml`.
